`tess` is the command-line client. It uploads files, a directory or a note, prints the link, and downloads shares. It can also list and delete your own shares, and it resumes an upload that was cut off. Run on its own, it opens a [full-screen view](#the-full-screen-view) for picking files and managing your shares.

## Install

On Linux and macOS:

```bash
curl -fsSL https://raw.githubusercontent.com/Limatura/tessera/main/scripts/install.sh | sh
```

The script downloads the build for your machine from the latest release, checks it against the release's `SHA256SUMS`, and puts `tess` in `~/.local/bin`. If that directory is not on your `PATH`, it tells you the line to add.

```bash
curl -fsSL https://raw.githubusercontent.com/Limatura/tessera/main/scripts/install.sh | sh -s -- --version 0.1.0 --dir /usr/local/bin
```

`--version` installs a particular release instead of the newest stable one, pre-releases included. `--dir` picks where it goes. `TESS_VERSION` and `TESS_INSTALL_DIR` do the same. Run the script again to update.

There are builds for Linux (x86_64 and arm64, static, so any distribution) and macOS (Intel and Apple Silicon). On Windows, download `tess-windows-x86_64.zip` from the [releases page](https://github.com/Limatura/tessera/releases).

To build it yourself, with Rust 1.97 or later:

```bash
cargo install --locked --git https://github.com/Limatura/tessera tessera-cli
```

## Sign in

You do not have to. Without an account, `tess send` uploads anonymously, as long as the instance allows that, and `tess get` never needs one. Signing in saves the instance, so you can leave out `--server`, and lets you upload as your account and use `tess ls` and `tess rm`.

```bash
tess login https://files.example.com
```

It shows a link, a short code and the link as a QR code. Open the link in any browser where you are signed in, check that the page shows the same code, and approve. It can be another machine, or your phone through the QR code, which helps over SSH when there is no browser to open. The request lasts 10 minutes.

An address without `https://`, such as `files.example.com`, means HTTPS. The same goes for `--server`.

The other two ways:

- `tess login --password https://files.example.com` asks for your username or email and password, and a code from your authenticator app if you use [two-step verification](/en/docs/accounts#two-step-verification). An account that signs in only with a passkey or an external provider has no password; use the browser.
- `tess login --with-token https://files.example.com` reads an API token from standard input, for scripts and CI. Make the token on your account page.

The browser and password ways create an API token named "tessera CLI on" plus the machine's name. It may create, list and delete your shares, and never more than your account may. Revoke it from your account page to sign that machine out.

The instance and token go in `~/.config/tessera/config.toml`, readable only by you. On Windows it is under your roaming app data. The saved token is only ever sent to the instance it came from: pointing `--server` at another instance sends no token.

## Send

```bash
tess send report.pdf
tess send photos/ notes.txt
echo "the wifi password is on the fridge" | tess send -
```

Everything named in one command becomes one share. A directory sends every file under it and keeps their paths. Empty files inside a directory are left out, because a share cannot hold an empty file unless it is encrypted. `-` reads a note from standard input; a note is a share of its own, so it cannot be mixed with files.

The link is printed on standard output and nothing else is, so `link=$(tess send report.pdf)` works. Progress and messages go to standard error, and progress only appears on a terminal.

| Option | What it does |
| --- | --- |
| `--expires <HOURS>` | How many hours the share lasts |
| `--max-uses <N>` | How many times it may be collected |
| `--password` | Asks for a password twice, or reads `TESSERA_PASSWORD` |
| `--encrypt` | Seals it on this machine, if the instance has end-to-end encryption on. See [end-to-end encryption](/en/docs/encryption) |
| `--qr` | Also draws the link as a QR code, for a phone to scan |
| `--copy` | Also puts the link on the clipboard |
| `--server <URL>` | The instance. Defaults to the one `tess login` saved, or `TESSERA_SERVER` |
| `--token <TOKEN>` | An API token. Defaults to the saved one, or `TESSERA_TOKEN` |

The password is never taken on the command line, where `ps` and your shell history would show it. Without `--encrypt` it is an ordinary share password. With `--encrypt` the key comes from it, so it has to be at least 12 characters.

`--copy` uses the desktop clipboard when there is one. Over SSH it asks your terminal to copy instead, which works if the terminal allows it.

### When an upload is cut off

Run the same command again. While it sends, `tess` notes how far it got in `~/.local/state/tessera/uploads/`, and the same files to the same instance carry on from there.

It starts over instead when a file has changed, or when the server has dropped the unfinished upload, which happens after `upload_session_ttl_hours` (24 by default). An encrypted send has to be resumed with the same password.

<Callout type="warn" title="An interrupted encrypted send leaves its key on disk">
  The part already uploaded is sealed with that key, so the rest needs it too. The file is readable only by you and is removed when the send finishes. Delete it yourself if you give up on the send.
</Callout>

## Fetch

```bash
tess get https://files.example.com/s/0ZPQ4M7K
tess get 0ZPQ4M7K -o downloads/
```

A code alone works when `tess` knows the instance, from `--server` or `tess login`. Files are written to the current directory, or the one `-o` names, and their paths are printed. A note is printed to standard output.

Fetching spends one of the share's collections, however many files it holds. If the share has a password, `tess` asks for it, or reads `TESSERA_PASSWORD`. An encrypted link opens with the key after `#`, so paste the whole link. If the instance is still scanning the share, `tess` waits up to five minutes.

`tess get` never overwrites a file that is already there. It also keeps only the ordinary parts of each file name, so a name like `../../.bashrc` lands as `.bashrc` inside the directory you chose.

## Your own shares

These need you to be signed in.

```bash
tess ls
tess rm 0ZPQ4M7K
```

`tess ls` lists your shares, newest first, with the code, the time left, the collections left and the name. A link share is named `(link)`. `tess rm` deletes one, by its code or its link.

## The full-screen view

Run `tess` on its own in a terminal. It opens the current folder full-screen, for picking files without typing paths, sending them, and managing your shares. When its input or output is not a terminal, `tess` prints the help instead.

The view uses the instance and token that `tess login` saved. It does not read `--server` or the `TESSERA_` variables. With no saved instance it starts on a welcome screen, where you can sign in. Browsing and finding files work without an account.

### Files and shares

The **Files** tab lists the folder. Mark files with Space, across as many folders as you like, and send them with Ctrl-S. With nothing marked, Ctrl-S sends the file under the cursor. Typing filters the list. Ctrl-F finds any file under the folder by a few letters of its path, and skips what `.gitignore` skips.

The **Shares** tab lists your own shares, with the expiry as a date and time on this machine's clock. Enter shows one in full, with its link and a QR code. An encrypted share's link is copied without its key, and the view says so.

Pasting a share link downloads it into the folder you are in. Ctrl-N writes a note or makes a link share.

| To | Keys | With vim keys |
| --- | --- | --- |
| Move | ↑ ↓, PgUp PgDn, Home End | j k, Ctrl-F Ctrl-B, g G |
| Go into a folder, or up one | → or Enter, ← or Backspace | l, h |
| Go back and forward through visited folders | Alt-← Alt-→ | H L |
| Mark one, mark all | Space, Ctrl-A | Space, a |
| Filter, find, go to a path | type, Ctrl-F, Ctrl-L | /, f, : |
| Send | Ctrl-S | s |
| Write a note or make a link share | Ctrl-N | n |
| Download from a link | Ctrl-G | p |
| Copy a share's link, delete it | Ctrl-Y, Del | y, d |
| Settings, transfers, order | F3, F4, F6 | F3, F4, o |
| Switch tab | Tab | Tab |
| See every key | F1 | ? |
| Quit | Ctrl-Q | q |

The mouse works too. Click a row to pick it, click its box to mark it, double-click to open a folder or send a file, and right-click for a menu. Dragging selects text and copies it when you let go. Without a desktop clipboard, the copy goes through the terminal, so it works over SSH if the terminal allows it. F2 turns the mouse off for the session, and the terminal does its own selection again.

### Sending

The send form offers what `tess send` does: encryption, a password, how long the share lasts and how many downloads it allows. It follows the instance. It hides encryption where the instance does not offer it, hides lifetimes longer than the instance allows, and asks you to sign in where uploads need an account. Ctrl-S sends from any field.

Sends and downloads run in the background, several at once. A dialog follows each one. **Hide** leaves it running, and F4 lists everything under way, with a way to stop each. When a send ends, its link and QR code show. Sending the same files again after a stop carries on from where it got.

QR codes are drawn as pictures in terminals that can show them, such as kitty, Ghostty, WezTerm, iTerm2, Windows Terminal and foot, and in half blocks elsewhere, inside tmux and screen included. VS Code's terminal shows pictures only with `terminal.integrated.enableImages` on.

### Settings

F3 changes the keys, the mouse, whether dotfiles show, the order and the colour. Each change is saved at once to the `[ui]` table of the config file.

```toml
[ui]
keys = "vim"        # or "standard"
mouse = true
show_hidden = false
sort = "modified"   # "name", "modified" or "size"
accent = "teal"     # violet, rose, orange, amber, green, teal or blue

[ui.bindings]
send = "ctrl-s"
up = ["k", "up"]
```

`[ui.bindings]` changes single actions. F1 lists each action's name. A key given there is taken away from whatever action had it before. An action, a key or any other entry in `[ui]` that `tess` does not know stops it at launch with an error.

Without `accent`, the view takes the colour you picked on the site, then the instance's own.

## Shell completion

`tess completions <shell>` prints a completion script. Supported shells are `bash`, `zsh`, `fish`, `elvish` and `powershell`.

```bash
tess completions zsh > ~/.zfunc/_tess
tess completions bash > ~/.local/share/bash-completion/completions/tess
```
